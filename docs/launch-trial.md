# Seven-day launch trial

This is a manually reviewed service request, not automatic activation or a paid package. The public form selects one or two bounded deliverables and carries the draft to the existing authenticated request form. The client explicitly saves it. The request retains launch-trial metadata; eligibility and dates are not client-controlled entitlements.

Operator workflow:

1. Review the business's prior trial requests and records before accepting. One trial per business; repeat accounts and duplicates need manual review.
2. Confirm the selected scope, approved source facts, capacity, start date and end date. The seven days begin on that agreed start date, not signup or submission.
3. Deliver the selected drafts manually using available authorized tools. No website connection to ChatGPT, Claude Code or Grok execution is added. Do not send customer material to another provider without the relevant authorization/privacy arrangements. Do not request client credentials.
4. Record accepted work and deliverables through the existing project/delivery administration process. Do not claim automated progress or delivery.
5. Allow one consolidated correction round on the original brief within the agreed trial period. Close at the agreed end. No card or renewal charge; separately scope any paid work.

No server-side trial activation, quota entitlement, countdown, automatic expiry, billing or external task execution is implemented here. The trial never writes `office_package_access`; Forge remains gated by actual active-package records. Stored request metadata indicates the requested offer, not acceptance. Eligibility is reviewed manually.

The six deliverable definitions and terms live in `dist/trial-model.js`, shared by the landing page, request import and signed-in AI service catalogue. Browser visuals and a real signed-in trial submission still require confirmation.
